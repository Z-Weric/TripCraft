# TripCraft 行程人工审核规范

本规范用于筛选可进入训练与离线评测流程的真实行程。审核对象是系统生成后、已通过基础程序校验的行程；审核结论不会触发在线训练或直接改变线上模型。

## 审核前提

- 样本必须来自脱敏导出，不得包含用户 ID、邮箱、电话号码、精确住址或自由文本中的个人信息。
- 审核员只审阅行程事实包、最终行程、验证报告和编辑差异；不得根据用户身份或历史行为判断质量。
- `fallback`、验证失败和低评分记录仅用于负样本与问题分析，不能作为 SFT 正样本。

## 审核维度

每个维度记录 `pass`、`minor_issue` 或 `reject`，并填写固定错误码。只有所有维度为 `pass` 的样本才能标记为 `gold`。

| 维度 | 通过标准 | 常见驳回原因 |
| --- | --- | --- |
| 景点真实性 | 每个 POI 都在批准事实包内，名称、坐标、费用和时长未被改写 | 虚构 POI、POI ID 不一致、费用或坐标篡改 |
| 路线合理性 | 同一天相邻 POI 地理上可达；不存在明显跨城往返 | 相邻距离异常、顺序明显绕路 |
| 预算 | 总费用不超预算；日费用与景点费用可核对 | 超预算、日费用或总费用计算错误 |
| 时间安排 | 天数匹配，每天有可执行内容；景点时长与移动时间不冲突 | 空白天、行程过密、跨天顺序错误 |
| 可读性 | 摘要、备注和交通建议清晰、准确、无重复和无不当承诺 | 无意义重复、语病影响理解、编造营业信息 |
| 偏好匹配 | 推荐理由能解释与用户偏好的关系，且不排斥显式约束 | 偏好完全未体现、推荐理由与 POI 不符 |

## 质量标签与处置

- `gold`：全部维度通过，且程序验证 `overall_valid=true`，用户评分至少 4（未评分样本需人工双签）。
- `silver`：无事实错误，但存在可编辑的文案或偏好匹配轻微问题；不得进入固定测试集。
- `fallback`：确定性规划器降级结果；用于基线比较，不进入 SFT 正样本。
- `negative`：验证失败、低评分或人工驳回；必须保留错误码，不能作为正向微调目标。

## 双人复核与切分

1. `gold` 与固定 `test` 集样本必须由两名审核员独立审核。
2. 结论不一致时，由第三名审核员裁决，并保留最终原因码。
3. 审核完成后，先运行 `build_dataset.py` 去重和切分，再开展训练。
4. 相同请求或相同 POI 序列不得同时出现在不同切分中；测试集一经发布不可回流训练集。

## 记录格式

审核记录应至少包含样本 ID、审核版本、每个维度结论、错误码、审核员代号、审核日期和最终质量标签。审核员备注不得写入可识别个人信息。
